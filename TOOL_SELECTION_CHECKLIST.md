# Automatic tool selection — NASA work

User instruction, 12 November 2026: after reviewing the full tool inventory, Sơn asked to use the tools automatically and not forget any. Apply this checklist without a plugin name or slash command. It is a durable selection rule, not a claim of perfect recall or a requirement to execute unrelated tools.

## Apply on every task

1. At session start and when the task changes category, scan all functional areas below and the 30-pack map. Match the current task and its required verification, not just the most obvious implementation tool. Reuse the current session's selection for unchanged work; do not reload every skill on every edit.
2. For each applicable area, discover the current tool, read the selected skill and LOCAL_USE guide, then actually use it. Prefer the existing adequate project tool. Alternatives serve the same job: choose one and record why; naming an installed tool is not invocation.
3. Record a compact coverage line in the task evidence/handoff: `area | selected tool | used / alternative selected / not applicable / unavailable | evidence or reason`. Record relevant missing capabilities and the safe fallback explicitly. Carry unresolved required checks into the next handoff; do not silently omit them.
4. Review the full change and independently check the result. Separate metadata exposure, file presence, invocation, earlier unrelated tests and current product verification. Report tools actually used and material limits briefly in chat.
5. Preserve task scope, one writer per checkout, competition timing and existing permissions. This instruction does not activate hooks, recording, passive memory, providers, spending, account/access changes, deployments or unrelated publication. Apply standing preparation sync when preparation documents change. Other machines must verify availability; a missing Mac runtime is not permission to install a duplicate stack.
